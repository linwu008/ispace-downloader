# CourseNest v1.0 发布候选验收

官网版本：1.0.0-rc.1。助手仍为 0.7.1，不重新打包分发，不强制升级。

## 本次变化

1. 区分网站刷新失败、未配对、电脑失联、助手暂停、学校未登录、目录待检查与可执行状态。失联不推断具体原因，显示最近收到消息的时间。
2. 任务显示待确认、待领取、执行、取消、完成阶段和状态更新时间；完成后展示助手报告的下载／跳过／失败数。超过十分钟无新结果给检查建议，不判定一定卡住，不伪造逐文件实时进度。
3. 关键操作立即禁用按钮并显示处理中；请求有超时和就近错误提示。刷新合并并发请求。网站任务在响应丢失后两分钟内重试复用请求标识，不自动重试写操作。
4. 学期默认值按北京时间计算，9 月至次年 1 月建议第一学期，2–8 月建议第二学期；这是可编辑建议，不代表学校校历。空白确认使用默认值；修改现有学期时清空仍保留原名称。切换只影响新存档，改名会更新原学期的显示名称。
5. 首次使用检查清单提供下载、配对、学校登录、课程目录和首次同步入口；依据近期状态判断，不把历史信息当实时验证。
6. 我的课程增加跨课程名称／文件名／Week 检索和未保存筛选。总览展示当前学期最近的作业要求和通知文字，每类最多八条，附原网页与提取时间。更早内容仍在课程和学期存档中。截止要求以学校原文为准，不自动猜测日期。
7. 手机优先展示待确认任务、电脑状态和课程要求；保留电脑设置的限制说明。增加中英文文案和窄屏检查。
8. 存档显示索引／文字、上次确认存在与缺失的文件数、最近成功导出时间和最新导出状态，可手动刷新。导出成功记录不证明电脑上的压缩包现在仍存在。

## 兼容与边界

- 沿用既有账号、配对、目录、任务和存档表；不执行破坏性迁移。
- 新增只读 `/api/v07/activity`，只返回登录用户当前学期的内容，响应有条数与节选长度上限。
- 新存档汇总字段是兼容性增量；原同步与旧助手能力判断保持。
- 未启动 R2、邮件、问答或付费服务。原文件仍在电脑，手机不能因此远程下载原文件；自助密码找回仍未开放。
- 仍需邀请码。官网更新与助手更新独立；新功能不要求重新下载安装包。
- 无法用测试账号证明真实学校当天一定可访问；正式发布前应在真实账号上确认一次配对电脑同步结果。

## 隔离验收环境

在项目根目录运行 `node cloud/staging.mjs`，访问 `http://127.0.0.1:18810`。

- 独立数据库 `.runtime/v1-staging/staging.sqlite3`，绑定本机地址。
- 不连接生产 D1；无 R2、邮件或 AI；邀请码 `NEST-LOCAL-04` 仅用于本地测试。
- 执行 `python scripts/check_release.py` 核对候选版本、静态文件、未登录 API 权限和关闭的服务。
- 不把真实账号或学校凭据复制到此环境。

## 验收命令与发布检查

- `node --test cloud/test/*.test.mjs`：云端、兼容性、权限、学期边界和状态模型。
- `python -m pytest -q`：助手与原有逻辑回归。
- `python scripts/check_ui_v1.py`：新状态恢复、搜索、丢失响应后去重、取消、手机、中英文、存档状态。
- 既有 `check_ui_v3.py` 至 `check_ui_v7.py`、`check_ui_public.py`：原有完整用户流程。
- `python scripts/check_bundle.py`：现有已打包助手的隔离启动检查；本次不发布新助手。
- `python scripts/check_release.py --origin https://bnbucoursenest.cn --production --wait 600`：只读线上冒烟，不创建真实账号或任务。

GitHub `Deployed website smoke check` 在 main 更新后自动执行，并支持手动运行。它等候构建传播，核对页面文件内容与提交一致；构建成功但线上文件未更新时仍报失败。

## 正式发布前

确认 CI、Workers Builds 和线上冒烟通过；用自己的电脑完成一次实际同步并查看下载结果；再将官网候选标记调整为正式版并重复线上验证。不要把候选标签当成已发布的 v1.0 标签。助手仍维持 0.7.1。

回退可在 Cloudflare 恢复上一 Worker 部署。本次没有数据库结构变更，不需要回滚用户资料；候选期新增的任务和存档继续保留。
